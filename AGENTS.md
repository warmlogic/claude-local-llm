# AGENTS.md — local-llm developer guide

This is the canonical contributor guide, at the repo root. `.claude/CLAUDE.md` is a symlink to this file, so Claude Code loads the same content as project memory.

Claude Code plugin that runs a small MCP server (houtini-lm, pinned) backed by a model running locally in LM Studio. Text in, text out, inference over loopback only, fenced read-only file access. The main session calls the plugin's tools directly, guided by a skill.

## Running tests

```bash
bash tests/test-fence.sh   # must pass before committing
```

Tests drive `scripts/launch-server.sh` over stdio MCP JSON-RPC (`tests/mcp-call.mjs`, node stdlib; `tests/fake-endpoint.mjs` is a loopback stand-in for LM Studio) using `mktemp` roots and generated synthetic fixtures. Needs `node`, `jq`, `curl`. Cases that need a model (happy path, oversized input) print `SKIP` when LM Studio is unreachable at `LOCAL_LLM_ENDPOINT_URL` (default `http://127.0.0.1:1234`); every fence case, the 1 MB cap and endpoint passthrough run without one. The oversized case assumes LM Studio loads the model at a 32k context and fails, not skips, if a 130k-char file is accepted. Scratch dirs under `tests/.tmp-*` are gitignored and removed on exit.

`tests/test-delegation.sh` is the delegation acceptance harness and is **not** part of the per-commit suite: every run is a real `claude -p` session and costs quota (a default run is 40 sessions: five each of a, a2, b, c, d and g, and ten for e's two turns, plus a few cheap judge calls). It loads the plugin with `--plugin-dir`, passes no `--allowedTools`, scores the stream-json traces with jq (tool uses joined to their results by `tool_use_id`), and treats an unparseable trace, a missing result event or a non-zero `claude` exit as a failed run. `DELEG_SELFTEST=1 DELEG_JUDGE=stub bash tests/test-delegation.sh` scores the hand-written traces in `tests/fixtures/deleg/` offline, and `test-fence.sh` runs that self-test on every commit (every assertion must pass, the printed total must equal the number of `expect*` lines, and a missing or unsummarizable fixture is an error, never a pass). Re-run the harness after editing `skills/delegate-local/SKILL.md`.

Cases (a case passes at 4 of 5):

- **a**: a 20k-char file is delegated unprompted (`code_task_files` succeeds on it; the footer houtini writes, the last `Model:` line of the result, must show a complete read equal to the number of paths and none of the bad-answer flags listed in the skill's names table, which is the only place the harness reads them from) and little of the file reaches Claude: exposure at most 0.10.
- **a2**: the same as a for a 25k-char prose document with a neutral name (`notes-0412.md`) and the prompt "Classify this document: <path>", which never names the tool or the size (real files do not carry `20k` in their names).
- **g**: the prompt "Use the local model to summarize <path>" on that document: delegated as in a, and no plugin permission denial.
- **b**: a 2k-char file is read directly: no `code_task_files` call, exposure at least 0.5.
- **c**: endpoint down: the tool fails with `fetch failed`, is not called again, and Claude reads the file itself (exposure at least 0.5).
- **d**: endpoint up with no model loaded (`fake-endpoint.mjs no-model`): the same, with `No models loaded`.
- **e**: one session, two turns (`--resume`), endpoint down. Turn 1 is as c and its final reply must tell the user about the outage with a cause and a way to retry; in turn 2 Claude reads the second file, makes no `code_task_files` call, and no assistant text block mentions the outage.
- **f**: no `permission_denials` entry names the skill call or a plugin tool in any inspectable trace of a to g. Other denials print as "other denials (not plugin)" and do not gate: with default permissions Claude's own compound shell commands can still prompt, as in any session.

**Exposure** answers "did the file's content reach Claude's context?" without listing read commands. Every line of a fixture carries two unique markers, its first and its last field (the log timestamp and an `eol=` id); a line counts as exposed when either appears in the text of any tool result, so `cut -f2-` does not hide it. Exposure is the fraction of the file's lines exposed, and the limit is that a reader which removes both markers evades the metric. The text of all tool results counts, the local model's answers included (an answer that echoes the file is the file reaching Claude). The two logs in case e use distinct token namespaces, so re-reading the first file cannot satisfy turn 2. The generated fixtures consist of whole lines, sized at or just under their target, so no marker is a fragment. Any tool or shell form that reads the file counts, and a narrow search for a pattern (a few lines) stays near 0. On the saved traces, delegated runs measured 0 to 0.09 and full reads measured 1.0, which is why the thresholds are 0.10 and 0.5.

**Judge.** Whether text mentions the outage is decided by one `claude -p --model haiku` call with tools off and a JSON schema (`mentions_local_model_unavailable`, `gives_cause`, `gives_retry`; the verdict is in the result event's `.structured_output`), cached by text. `DELEG_JUDGE_CHECK=1 bash tests/test-delegation.sh` scores it against 24 labeled messages in `tests/fixtures/deleg/judge-labels.json` (the phrasings reviewers raised plus log sentences that must not count) and needs at least 23; the current prompt scored 24/24 in four of five checks and 23/24 in the fifth. `DELEG_JUDGE=stub` swaps in canned verdicts from `judge.json` for the offline suite.

Knobs: `DELEG_RUNS` (5), `DELEG_CASES` ("a a2 b c d e g"), `DELEG_MODEL`, `DELEG_OUT` (trace dir, kept), `DELEG_ALLOWED_TOOLS` (passed to `--allowedTools`; setting it voids the no-prompt result, since it grants the permissions under test), `DELEG_SETTING_SOURCES` (default `project`, which keeps the user's own settings, allow rules and hooks out; hooks are not disabled because the plugin's own hook approves the skill call). Cases a, a2, b and g need LM Studio to list a model at `127.0.0.1:1234`; a skipped case makes the run exit non-zero. Needs `claude`, `jq`, `node`, `curl`, `shasum` and `timeout` (or `gtimeout`).

Measured at the current skill and hooks with the default model: a 5/5, a2 5/5, b 5/5, c 5/5, d 5/5, e 5/5, g 4/5, f 0 plugin denials in every inspectable trace (about 40 per full pass). The g miss was a local-model answer that ran to the token limit (a `Quality:` flag), which the skill correctly discarded in favor of reading the file. On the whole-line fixtures, the share of the file quoted back by the 9 delegated a2 and g answers was 0 in 8 and 0.01 in 1; earlier runs on fixtures whose last line was cut showed one runaway answer at 0.09. The outage path says to read the whole file with `Read`; without that, the spot-check rule for delegated answers made fallback reads sample the file and e dropped to 1/5 to 3/5 across runs. Within a single turn the model reliably writes an outage note at the failure and recaps it in the final reply, and no wording suppressed that, which is why e spans two turns.

## Project layout

```text
.claude-plugin/
  plugin.json        # name/description/userConfig — unversioned; see "Unversioned" below
package.json         # no dependencies; pins npm's project root to the plugin (see launch-server.sh)
.mcp.json            # one server, local-llm: runs scripts/launch-server.sh, passes userConfig via env
skills/
  delegate-local/SKILL.md  # when and how Claude hands big text jobs to the local model; one table holds every server-specific name
hooks/
  hooks.json         # PreToolUse (Skill and code_task_files): approve-own-tools.mjs; UserPromptSubmit: size-hint.mjs
scripts/
  approve-own-tools.mjs # allows this plugin's own skill call and, by exact name, code_task_files; silent for everything else
  size-hint.mjs      # adds a one-line hint when the prompt names an existing file of 10,000+ bytes (stat only)
  launch-server.sh   # fail-closed checks, scrubs and sets HOUTINI_* env, execs the pinned houtini
  resolve-roots.mjs  # resolves allowed folders with houtini's own split/trim/realpath semantics
tests/
  test-fence.sh      # fence + launcher + model-backed cases
  mcp-call.mjs       # minimal stdio MCP client used by the tests
  fake-endpoint.mjs  # loopback HTTP listener that logs request headers; `no-model` mimics LM Studio with nothing loaded, `error500` fails every chat with HTTP 500
  test-delegation.sh # delegation acceptance harness (real claude -p sessions; not in the per-commit suite)
  fixtures/deleg/    # hand-written stream-json traces, tiny target files, canned judge verdicts and judge labels
```

## Non-obvious design decisions

- **The launcher exists because houtini fails open, and it validates what houtini will use.** With `HOUTINI_LM_FILE_ROOTS` unset or empty, houtini's `code_task_files` reads any absolute path. Houtini also parses the variable as `split(/[:,]/).map(trim).filter(Boolean)` and `realpathSync`s each piece, so a string check in sh is not enough (`/repo:archive` adds a cwd-relative `archive`; `//` and `/tmp/..` resolve to `/`; a root ending in U+FEFF or NBSP is trimmed into a sibling). `scripts/resolve-roots.mjs` therefore runs in node with houtini's exact parse: it expands `$HOME`/`${HOME}`/`~`, refuses relative entries and any `:`, refuses any entry with leading or trailing whitespace (entries are never trimmed, so padding cannot silently name a sibling folder; Claude Code joins the option with a bare `,`), resolves with `realpathSync.native` (on-disk case, matching houtini's per-file realpath on case-insensitive APFS; houtini's own `realpathSync` returns that result unchanged), and refuses unless houtini's parse of the resolved path yields exactly that path. A resolved `/` is refused; a nonexistent folder (a default missing on this machine) is skipped with a warning, and if every folder was skipped the launcher says none exist; any other resolution error (`EACCES`, `ENOTDIR`, `ELOOP`) or a non-directory exits 2. `launch-server.sh` exits 2 before starting houtini when no folder remains, and logs the resolved roots on stderr. The launcher also requires `node` and `npx`, and `cd`s to the plugin root (`CDPATH` cleared) before resolving and exec'ing. The root's `package.json` pins npm's project root there, so a stray `node_modules` in an ancestor directory cannot win either. Why: Claude Code spawns the server with the session's project dir as cwd, and `npx` runs a matching `@houtini/lm` found in `node_modules` up the cwd's ancestry (and reads a project `.npmrc`), so a repo carrying one would execute its code. Never launch houtini from `.mcp.json` directly.
- **Houtini's other environment variables are scrubbed.** The launcher unsets every `process.env.*` variable houtini 3.3.4 reads (`LM_STUDIO_*`, `OPENROUTER_API_KEY`, `HOUTINI_LM_STRUCTURED`, ...) before exporting the ones it sets, so ambient values cannot change routing or credentials. `tests/test-fence.sh` reads the list from the launcher, checks the environment a stub `npx` receives, and (when a cached 3.3.4 dist exists) fails if the dist reads a variable that is neither scrubbed nor exported; re-derive the list from the dist when bumping the pin.
- **`allowed_dirs` is a `directory` option with `multiple: true`.** Claude Code joins the array with `,` on `${user_config.allowed_dirs}` substitution, which is one of the separators houtini splits on (`:` or `,`). Consequence: folder names cannot contain `,` or `:`. Defaults (`$HOME/github`, `$HOME/catalyst`) reach the launcher literally, and a headless `--plugin-dir` run applies them without prompting; the resolver expands a leading `$HOME`, `${HOME}` or `~` (Claude Code itself expands only `${HOME}`). The value travels in `LOCAL_LLM_ALLOWED_DIRS`, not argv, so an empty value cannot vanish as an argument.
- **The endpoint must be loopback.** The launcher accepts only `http(s)://` URLs whose host is `127.0.0.1`, `localhost` or `[::1]` (no userinfo), so a misconfigured `endpoint_url` cannot send file contents to a remote server. The check covers the inference endpoint only; see the next bullet.
- **Accepted risk: houtini's Hugging Face metadata lookup.** At startup, and again every 7 days per cached model, houtini 3.3.4 sends the loaded model's id (never file text) to `huggingface.co/api/models/...` to fetch model metadata (`dist/model-cache.js`). No setting in 3.3.4 disables it, and the loopback check does not cover it. So the accurate claim is narrower than "nothing leaves the machine": the plugin never sends file text to a remote model server. What Claude itself receives (the local model's answer, any spot-check lines, a fallback read) goes to Anthropic like any other Claude Code context.
- **Fence semantics are houtini's.** Roots and files are `realpath`ed before comparison, so symlinks out of a root and sibling-prefix directories (`root-evil` next to `root`) are rejected; the rejection never echoes file contents.
- **`HOUTINI_LM_API_KEY=not-needed`.** LM Studio needs no key; setting a dummy stops houtini from falling back to `OPENROUTER_API_KEY` from the user's environment.
- **`HOUTINI_LM_STRUCTURED` stays unset.** Plain text output is the contract.
- **`HOUTINI_LM_MAX_FILE_MB=1`** (houtini's minimum) caps a single read well below the context window's reach.
- **`npx -y @houtini/lm@3.3.4` with `npm_config_prefer_offline=true`.** The exact pin keeps the fence code reviewed; the offline preference makes startup hit the npx cache (about 0.4 s warm) instead of the registry. Never pin below 3.3.3: 3.3.0–3.3.2 hid answers from Claude Code. Re-run `tests/test-fence.sh` when bumping the pin. The first launch on a cold npx cache needs network and can take a few seconds; if the server times out, reconnect via `/mcp`. The launcher exits 2 with a clear message when `npx` is missing.
- **Oversized input is a hard error, not a truncated summary.** The limit is the loaded model's context window in tokens, not houtini's byte cap. Dense synthetic text runs about 2.7 chars/token, so ~80k chars (~30k tokens) still fit a 32k context while ~90k+ chars return `Error: Upstream model error mid-stream: ... context_length_exceeded` and no summary. Houtini does not truncate silently. A size check before delegating is still the skill's job, because the error costs a round trip and real prose tokenizes at a different rate.
- **The skill's thresholds are rules of thumb; its table is the swap seam.** `skills/delegate-local/SKILL.md` delegates a bounded text job over roughly 10k to 60k characters: below 10k, reading it is cheaper than the round trip; the 60k ceiling comes from the 32k context and the measured ~2.7 chars/token (80k fits, 90k errors), with margin for real prose, and stays a guess until measured on real files. Claude gets the size from `wc -c` without reading the file. Every houtini-specific name (tool, footer field, error and quality-flag string, the `allowed-tools` line) sits in the skill's one table, taken from houtini 3.3.4's dist; swapping the server edits that table and the frontmatter only. The skill loads into every session, so it stays under 80 lines (`test-fence.sh` checks).
- **Permissions (headless `claude -p`, no `--allowedTools`).** A skill's `allowed-tools` pre-approves the MCP tool for the turn that invokes it (negative control: the same skill without the line has `code_task_files` denied). It cannot approve the `Skill` call that loads it: without a rule that call is denied and the model falls back to calling the tool, which is also denied. A plugin cannot ship allow rules in `settings.json` (only `agent` and `subagentStatusLine` take effect), so `hooks/hooks.json` ships a `PreToolUse` hook (`scripts/approve-own-tools.mjs`) that allows exactly `local-llm:delegate-local` and, by exact name, the read-only tool `mcp__plugin_local-llm_local-llm__code_task_files`; every other houtini tool (`chat`, `custom_prompt`, `embed`, ...) stays unapproved, and a later server that wants its own tool approved adds that name itself. The tool is safe to approve because the launcher fences it to the allowed folders, it only reads, and inference stays on loopback. Its name matters because asking plainly ("use the local model to ...") can make Claude load `code_task_files` through ToolSearch without the skill, and `allowed-tools` only applies once the skill is loaded. Deny rules still win over the hook: the hooks reference says so, and a live run with `--disallowedTools mcp__plugin_local-llm_local-llm__code_task_files` and case g's prompt removed the tool from Claude's pool (ToolSearch answered "No matching deferred tools found"), so it read the file itself. A `UserPromptSubmit` hook (`scripts/size-hint.mjs`) stats the path-like tokens in the prompt (absolute, `~/`, or relative to the hook input's `cwd`; at most 100 stat calls) and, for up to three regular files of 10,000 bytes or more, adds `local-llm: <path> is about N bytes; if the job is a bounded read-only text task (summarize, classify, extract), the delegate-local skill applies.`; it never reads file contents. `wc -c` and other read-only shell commands are auto-allowed, but compound or piped shell commands are not, so the skill sends Claude to the Read and Grep tools. Do not run the harness with `disableAllHooks`, which disables that hook; `--setting-sources project` keeps user hooks out instead.
- **Tool names** for a plugin server are `mcp__plugin_local-llm_local-llm__<tool>` (`code_task_files`, `discover`, ...); use the full name in `allowed-tools` and permission rules.

## Unversioned

This plugin carries no `version` field in `.claude-plugin/plugin.json`. Claude Code keys an unversioned install by the git commit SHA of the source, so every merge to `main` is a release. `claude plugin validate .` warns "No version specified" for this; that one warning is expected and accepted. Don't add a `version` field to silence it.

## Don't edit the plugin cache

The installed copy lives under `~/.claude/plugins/cache/` and is overwritten on plugin update. Edit the source repo and reinstall. To try a change without installing, run `claude --plugin-dir <worktree>`.
